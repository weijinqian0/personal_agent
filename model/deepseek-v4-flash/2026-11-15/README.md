## 1. 任务上下文与当前输入

用户先询问DeepSeek V4的HBM，并逐步确认Flash、A5、原生权重量化、KV FP8、8192 batch tokens/DP及DSpark3层；随后要求补hybrid padding、权重、激活、共享专家多流、图池/HCCL、异步KV×2，以及512K/1M/2M序列对比和扇形图。

| 参数 | 当前值 | 状态/解释 |

| 模型/硬件/后端 | DeepSeek V4 Flash、A5、vLLM-Ascend | 用户确认；实际checkpoint与软件镜像revision未提供 |

主KV行608B包含FP8 NoPE、BF16 RoPE/scale与行padding；Indexer行132B=128B FP8＋4B FP32 scale；compressor state保持FP32。主KV/Indexer不是常规独立K/V各一份，不机械再乘2。

对本快照的对齐长度L、固定单chunk8192，单批已知页映射为：

```text
K_single(L) = 592000 × (L/128 + L/4096 + 6700) bytes
K_user_x2(L) = 2 × K_single(L)
K_two_inflight(L) = 592000 × (L/128 + L/4096 + 13356) bytes
```

长历史随L增长；SWA/state活跃页依本轮chunk而定，所以不能把整个128K的4.276GiB按序列长度等比放大。×2系数和双在途页并集独立列示，不再重复乘2。固定KV池内持块增加不等于设备再申请一份整池。

各激活阶段取max，不把所有阶段/层数相加。前面的约1.14GiB初算后来按DSpark capture边界修正为1.078GiB：最后主层内已有两份aux，第三份在该层后产生。eager调用者的mHC/residual引用、外层o_proj_input和独立attention result、shared-expert gather与多流重叠均影响存活。

原生FP4权重路径的GMM1输出仍是BF16；SwiGLU包装即使output_origin=false仍申请BF16 origin，均衡参考为48MiB。HCCL按收发两份和实际独立域计，不按peer或层数乘；MC2可能在初始化/decode保留。图池/通信池/非Torch差分与张量storage应去重，reserved包含allocated，不能相加。

概率draft缓存依赖`max_num_seqs×num_speculative_tokens×vocab×head_dtype_bytes`，例如256×15×129280×4=1.849365234GiB；这些256/15/FP32不是已确认输入，未并入基线。非KV跨批留存也尚未完整定量。

## 5. 长序列已计项规划预算

统一权重12.631970517、主干激活核心1.078277588、已知持久项0.328125GiB；只对KV采用用户×2。图池范围1–2GiB。每格仍需加Δ(L)，不构成完整设备峰值。

| 长度 / tokens | 单批KV映射 GiB | 用户KV×2 GiB | HCCL B=200 已计项GiB | B=1024 | B=2048 |
|---|---:|---:|---:|---:|---:|
| 128K / 131072 | 4.276216 | **8.552432** | 24.860336–25.860336 | 26.469711–27.469711 | **28.469711–29.469711** |
| 512K / 524288 | 6.022871 | **12.045741** | 28.353645–29.353645 | 29.963020–30.963020 | **31.963020–32.963020** |
| 1M / 1048576 | 8.351743 | **16.703486** | 33.011391–34.011391 | 34.620766–35.620766 | **36.620766–37.620766** |

```text
Accounted(L,B) = K_user_x2(L) + W_EP16 + A_core + P_known
                 + (900+2B)/1024 GiB + graph[1,2] GiB
```

Δ(L)表示权重物理差额/额外池、KV实际分配与额外保留差额、未覆盖激活/workspace/完整draft-logits阶段、额外通信/持久资源、runtime/allocator及非KV异步增量。因为每DP本轮固定8K，主干激活核心沿用相同值；不意味着随历史增长的workspace/metadata也恒定。

扇形图各长度分开绘制，以**B=2048、图池2GiB**的已计项小计为分母；不是整卡容量占比。128K/512K/1M/2M小计分别为29.469711/32.963020/37.620766/46.936257GiB，且不含Δ(L)。

**2M为容量外推。** 本地参考config的max_position_embeddings=1048576（1M）；没有证明实际checkpoint/RoPE/backend可运行2M。硬件每卡容量也未给，因此不提供可部署/剩余空间/并发结论。

## 6. 对话中修正与后续继续入口

1. KV初始组件小计没有覆盖hybrid空槽，补出0.921GiB，单8K已知页映射为4.276GiB。
2. 权重区分原生运行scale、额外副本和EP16/实际EP4放置，不能按top6激活比例缩小驻留专家。
3. 激活按mHC/aux真实时点修正1.14→1.078GiB，并纳入共享专家多流；workspace仍未知。
4. 用户指定图池1–2GiB；HCCL按域配置而非固定整卡常数处理。
5. 用户要求异步KV×2后，把其作为明确的规划系数写入主预算，并保留双8K页并集对照。
6. 用户要求HTML和每长度扇形图，最终交付独立离线页面；不依赖聊天图表运行环境。

后续优先补：真实启动命令/最终配置、EP4的准确含义、模型和后端版本、max_num_seqs/投机tokens/采样dtype、实际KV池与每组块数、完整workspace与图捕获/通信域/设备内存快照。获取新证据后应建立新快照，不把归档假设改称实测。
