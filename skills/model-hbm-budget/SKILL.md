# 模型完整 HBM 预算

用户只提供模型名并要求“估算 HBM/显存占用”时从本入口处理完整推理预算。仅问权重、KV 或激活时直接调用对应专项，不扩大范围。训练显存不套用本流程。

## 背景与目标

目标是生成总体模型的 HBM 空间占用。必须先拆解并分别计算各模块，再去重汇总；不能只给整模型参数量乘dtype、单一经验总数，或用“容量减权重”的余额代替其他模块计算。

分两级建账：先按 KVCache、权重、激活/workspace、图池、HCCL buffer、其他持久项和运行时分类；每类继续拆到实际相关模块，例如 Attention/Indexer/compressor、Dense/MoE/共享专家、Embedding/head、Engram、视觉和投机模块，以及各缓存组、图池和通信域。按物理存储归属计费，跨模块共享只记一次。

每个适用模块必须交付“参数/来源 → 公式 → 数值代入 → bytes/GiB → rank/阶段 → 已知或未知状态”，再由模块小计导出分类小计和同阶段模型总账。缺项保留符号，不因需要总体结果而填零或猜数。内部核算和报告展示都先分模块计算，再做异步增量、去重合账；总体汇总表只放在报告末尾，不在开头预告整体占用。

## 默认负载与模块计算表

- 用户未特别指定、实际部署或负载资料也未确定取值时，采用序列参考长度L=128K=131072 tokens、连续前缀命中率h=90%。缺哪个字段只补哪个字段；用户值与已确认实际值优先，不重复询问默认长度/命中率。标注“用户约定的估算假设”，不把L当max_model_len，不补造并发数、输出长度或在途批次数。
- 命中率按每请求连续prefix的条件场景解释。KV专项按有效命中粒度向下对齐并展示目标命中量、有效prefix及未命中量；不擅自启用prefix caching，不把服务平均命中率当连续prefix。实际配置关闭prefix时报告实际命中与90%假设的冲突，假设场景不能冒充实际结果。命中prefix仍可能占KV，不把总HBM乘10%。
- 每个模块的中间计算必须用表格呈现：`具体模块 | 参数/来源 | shape与dtype或记录/页/块 | 公式及数值代入 | 整数bytes | MiB/GiB | rank/阶段 | 状态/缺项`。表格可为可读性拆分，但不能只给文字、公式代码块或最终GiB。模块内有小项时列子项与去重小计，尚未确定的小项仍列条件式。
- 模块表覆盖KVCache、权重、激活/workspace、图模式/图池、HCCL buffer、其他持久量、runtime及异步增量。总体汇总仍在末尾，结果写完整名称和明确条件。

## 调用流程

1. **一次收集共用输入**：读取已有对话、部署命令、模型 config/header、目标硬件、版本与相关源码差异，建立一份参数/证据表，标注用户值、有效默认、参考场景与未知。用户授权采用仓库推荐配置时先查完整示例；只问仍影响结果的关键选择，不重复索取已知值。不把历史算例或不匹配的上游代码当当前事实。
2. **加载三个专项并共享输入**：读取同级目录的 `weight-hbm-estimation/SKILL.md`、`kv-cache-budget/SKILL.md`、`activation-hbm-estimation/SKILL.md`；只按当前模型需要追加 references。每项输入只核对一次，变更后更新所有依赖结果。若专项缺失，报告缺失并继续独立分项；不能声称已完成全部调用。
3. **形成分账，而非拼接三份回答**：权重专项交接 W 和加载转换副本；KV 专项先交接组件/物理页/组几何与需求 K_need；激活专项拆分 A、G、C、P、R。完整交接规则见[HBM 指南](references/hbm-guide.md)。读取 skill 只是加载方法；产出该专项的公式、数值或明确未知项后才算完成相应分账。
4. **闭合 KV 预算**：按实际初始化顺序，先确定非 KV 占用及 profile/capture 策略，再从实际分配规则或日志求 K_pool，回查 K_need 是否满足各组块数。检查图捕获是否晚于 KV 分配，不能把利用率目标当最终设备峰值。未知池容量保留条件式，不用请求有效载荷代替整池。
5. **按 rank 与阶段去重合账**：先按异步核算规则计算KV在途需求及非KV跨批物理增量，再去重合账。同一物理存储只归一类；同 rank、同一时刻求和，再取所有 rank/阶段最大值。分别覆盖加载/转换、profile/warmup、图捕获、prefill、decode/投机及实际相关的混合调度/PD交接。P/D独立，节点和全实例总量仅作辅助。
6. **异步核算与末尾汇总交付**：按[报告模板](references/report-template.md)先展开配置、各模块计算表、异步增量表及逐阶段合账表，再在末尾给总体汇总表。主要计算保留在正文，不能只提供附件链接。

## 统一占用分类与末尾总体汇总

最终答复和报告先给配置/证据、模块计算、异步增量、阶段合账及缺项，最后给总体汇总表。缺少参数时先完成可独立计算的模块并集中补问；末尾汇总保留已有值、条件式和待确认项。关键未知确认前不输出依赖关键未知的唯一完整总数。

| 必列类别 | 计费边界 | 专项 owner |
| --- | --- | --- |
| KVCache（K） | 实际预分配池及池外独立 cache/state；需求另列，不重复加进总账 | KV |
| 权重（W） | 加载后权重、量化元数据、实际额外权重副本 | 权重 |
| 激活与 workspace（A） | 同阶段临时张量/算子工作区；持久部分另归 P | 激活 |
| 图模式 / 图池（G） | eager/FULL等模式及 target/draft 捕获后的去重增量 | 激活 |
| HCCL buffer（C） | 已初始化且去重的实际通信域缓冲及明确归属的辅助量 | 激活 |
| 其他持久缓冲 / 通信池（P） | 非 KV、非权重的共享buffer，独立MC2/SHMEM等；排除已计 C/G | 激活 |
| 运行时与分配器额外量（R） | 尚未计入的ACL/driver/allocator slack等，排除已含 C/G/P 的量 | 激活 |

末尾汇总表列 `类别 | 单卡占用 GiB / 条件式 | 阶段或口径 | 证据状态 / 缺项`，另列已核算小计/完整总计、容量/预算目标、剩余空间。不适用或已确认关闭可写0并给依据；未知写符号或待确认，不能留空、写0或藏入“其他”。启用图模式本身不是图池字节证据；148MiB持久buffer一类局部小计不能标成完整激活。

各行必须属于同一 rank、同一参考阶段才能相加；若各行是不同阶段峰值，标为“分项峰值、不可直接相加”，总计由逐阶段矩阵导出。`non_torch` 无法拆分时标注一个跨行合并量及覆盖范围，已包含的行写“含于non_torch合并测量值”，不重复计费；末尾汇总表仍保留 G/C/P/R 行及状态。

数值总计必须标明“完整 / 条件 / 已知小计”及未知补充项；有未知时剩余空间仅写条件余量，不能称可用 KV。已确认的完整总计才用于容量判断。保留独立安全余量，不冒充实测占用。

## 异步调度核算与独立可读性

- 先确认运行版本中async有效开关、最大在途批次数B、每DP公共batch token预算T、投机验证位置及实际请求组合。不能把未填写当关闭，也不能把B默认设为2。
- KV专项按安全结算基线与全部未结算批次，交接主KV、Index/folded、SWA、compressor/state、target/draft的新增和延迟释放块，保留每组的基线块数、异步块数、差额及bytes。
- 激活专项按跨批存活关系交接输入/输出、hidden/draft state、采样/metadata、通信staging和图descriptor buffer增量。B批在途不等于B次forward同时运行；不能将全部A/G/C机械乘B。
- 异步持块已包含于固定K_pool时，只改变KV供需和并发余量，不再次增加模型HBM。自适应KV池可能因异步非KV开销而缩小，需沿profile/capture实际预算核对。
- 必须给出“已定量计入 / 有依据的零增量 / 尚未完成定量核算”状态及来源。只保留额外块O或未知U，不得声称已完整包含异步。
- 报告不使用“上述、同上、该项、其余、见前文”等上下文指代；重复具体模块名、配置、角色/rank、阶段和必要条件。公式变量在出现位置定义；末尾汇总不能只列未解释的K/A/G/C/O/U。

## 细节与范围

详算模块顺序：KVCache → 权重 → 激活/workspace → 图模式/图池 → HCCL buffer → 其他持久项 → 运行时 → 逐阶段总账。权重与KV可能在内部先算，输出顺序不代表执行依赖顺序。

沿用 KV 专项的多请求、投机预算范围及 `block_size=128` 条件回退；这些不证明部署已开启投机或采用该block。不得固定某模型 GiB、HCCL 域数、图池经验值或并发数。没有设备时交付可复算条件账，不能为补齐表格臆造实测峰值。
