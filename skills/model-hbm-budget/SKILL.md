# 模型完整 HBM 预算

这是三个专项 skill 的编排入口，不另造替代算法。用户只提供模型名并要求“估算 HBM 占用”时，按完整推理部署预算处理；不要仅用参数量乘 dtype 回答。

## 联动三个 skill

定位并读取同一安装目录下的三个 `SKILL.md`，然后按当前模型读取各自必要 references：

| Skill | 负责的结果 |
| --- | --- |
| `weight-hbm-estimation` | 各 rank 常驻权重、量化元数据、额外权重副本和加载转换峰值 |
| `kv-cache-budget` | 主 KV/索引/窗口/状态、投机缓存、请求物理持块及整池容量 |
| `activation-hbm-estimation` | 非权重非 KV 的激活、workspace、通信、图池、持久缓冲和运行时峰值 |

在本仓库中分别位于 `../weight-hbm-estimation/`、`../kv-cache-budget/`、`../activation-hbm-estimation/`。安装时保留四个同级目录。若专项 skill 不可用，明确指出缺失依赖，继续已可核对分项；不能声称已调用全部三个或完成总预算。

读取 [完整 HBM 占用指南](references/hbm-guide.md)，按以下交接执行：

1. 建立三者共用的配置与证据表：模型 revision、checkpoint、硬件、后端版本/源码差异、启动配置、P/D、rank/并行组、负载、投机、量化和 offload。先从现有资料获取，集中询问仍决定结果的未知项。
2. 应用权重 skill 得到逐 rank 权重账；应用 KV skill 得到组件和池几何；应用激活 skill 得到逐阶段非 KV/非权重账。KV 池尚未确定时，先求非 KV 预算，再按该版本实际分配策略求池，回到 KV skill 验证请求能否容纳，避免循环假定。
3. 用唯一物理存储身份和生命周期交接分项，明确每项唯一 owner；权重附表中的非权重持久缓冲交给激活账，KV/state 与其临时 staging 分开，图池整体和其内部张量不重复计入。
4. 按同一 rank、同一时刻合账，分别报告加载/转换、warmup/图捕获、prefill、decode、投机和混合调度中相关阶段。P/D 独立核算。独立峰值之和仅在有依据时作保守界，不当实际峰值。
5. 交付配置与证据、三个专项分账、逐阶段总账、最大单卡/最小余量、KV 供需对比、未知项和复算过程。关键未知未确认前只交付条件预算/已确认小计，不给唯一完整总数或可部署保证。

KV 默认多请求、包含投机场景的范围约定及 `block_size=128` 条件回退沿用 KV skill；它们不是已启用投机或实际 block 大小的证据。用户明确配置优先。仅询问方法时交付指南即可，无需制造模型数值或索取部署参数。
