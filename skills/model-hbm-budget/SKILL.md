# 模型完整 HBM 预算

用户只提供模型名并要求“估算 HBM/显存占用”时从本入口处理完整推理预算。仅问权重、KV 或激活时直接调用对应专项，不扩大范围。训练显存不套用本流程。

## 背景与目标

目标是生成总体模型的 HBM 空间占用。必须先拆解并分别计算各模块，再去重汇总；不能只给整模型参数量乘dtype、单一经验总数，或用“容量减权重”的余额代替其他模块计算。

分两级建账：先按 KVCache、权重、激活/workspace、图池、HCCL buffer、其他持久项和运行时分类；每类继续拆到实际相关模块，例如 Attention/Indexer/compressor、Dense/MoE/共享专家、Embedding/head、Engram、视觉和投机模块，以及各缓存组、图池和通信域。按物理存储归属计费，跨模块共享只记一次。

每个适用模块必须交付“参数/来源 → 公式 → 数值代入 → bytes/GiB → rank/阶段 → 已知或未知状态”，再由模块小计导出分类小计和同阶段模型总账。缺项保留符号，不因需要总体结果而填零或猜数。内部核算先分后总；对用户仍先给总体汇总表，再展开模块计算。

## 调用流程

1. **一次收集共用输入**：读取已有对话、部署命令、模型 config/header、目标硬件、版本与相关源码差异，建立一份参数/证据表，标注用户值、有效默认、参考场景与未知。用户授权采用仓库推荐配置时先查完整示例；只问仍影响结果的关键选择，不重复索取已知值。不把历史算例或不匹配的上游代码当当前事实。
2. **加载三个专项并共享输入**：读取同级目录的 `weight-hbm-estimation/SKILL.md`、`kv-cache-budget/SKILL.md`、`activation-hbm-estimation/SKILL.md`；只按当前模型需要追加 references。每项输入只核对一次，变更后更新所有依赖结果。若专项缺失，报告缺失并继续独立分项；不能声称已完成全部调用。
3. **形成分账，而非拼接三份回答**：权重专项交接 W 和加载转换副本；KV 专项先交接组件/物理页/组几何与需求 K_need；激活专项拆分 A、G、C、P、R。完整交接规则见[HBM 指南](references/hbm-guide.md)。读取 skill 只是加载方法；产出该专项的公式、数值或明确未知项后才算完成相应分账。
4. **闭合 KV 预算**：按实际初始化顺序，先确定非 KV 占用及 profile/capture 策略，再从实际分配规则或日志求 K_pool，回查 K_need 是否满足各组块数。检查图捕获是否晚于 KV 分配，不能把利用率目标当最终设备峰值。未知池容量保留条件式，不用请求有效载荷代替整池。
5. **按 rank 与阶段去重合账**：同一物理存储只归一类；同 rank、同一时刻求和，再取所有 rank/阶段最大值。分别覆盖加载/转换、profile/warmup、图捕获、prefill、decode/投机及实际相关的混合调度/PD交接。P/D独立，节点和全实例总量仅作辅助。
6. **先表后计算交付**：严格采用下面的首表规则与[报告模板](references/report-template.md)，然后按相同顺序展开参数、公式、代入、整数 bytes、单位转换、来源及未覆盖项。不要把读者引到附件才能看到主要计算。

## 统一占用分类与首表

最终答复和报告均先给汇总表；表前最多一行说明配置、rank/角色和估算口径。不要先铺陈 skill 调用、源码调查或公式。缺少参数时也先给已有值/条件式/待确认的表，再集中补问；关键未知确认前不输出依赖它的唯一完整总数。

| 必列类别 | 计费边界 | 专项 owner |
| --- | --- | --- |
| KVCache（K） | 实际预分配池及池外独立 cache/state；需求另列，不重复加进总账 | KV |
| 权重（W） | 加载后权重、量化元数据、实际额外权重副本 | 权重 |
| 激活与 workspace（A） | 同阶段临时张量/算子工作区；持久部分另归 P | 激活 |
| 图模式 / 图池（G） | eager/FULL等模式及 target/draft 捕获后的去重增量 | 激活 |
| HCCL buffer（C） | 已初始化且去重的实际通信域缓冲及明确归属的辅助量 | 激活 |
| 其他持久缓冲 / 通信池（P） | 非 KV、非权重的共享buffer，独立MC2/SHMEM等；排除已计 C/G | 激活 |
| 运行时与分配器额外量（R） | 尚未计入的ACL/driver/allocator slack等，排除已含 C/G/P 的量 | 激活 |

首表列 `类别 | 单卡占用 GiB / 条件式 | 阶段或口径 | 证据状态 / 缺项`，另列已核算小计/完整总计、容量/预算目标、剩余空间。不适用或已确认关闭可写0并给依据；未知写符号或待确认，不能留空、写0或藏入“其他”。启用图模式本身不是图池字节证据；148MiB持久buffer一类局部小计不能标成完整激活。

各行必须属于同一 rank、同一参考阶段才能相加；若各行是不同阶段峰值，标为“分项峰值、不可直接相加”，总计由后续阶段矩阵导出。`non_torch` 无法拆分时标注一个跨行合并量及覆盖范围，已包含的行写“含于该量”，不重复计费；首表仍保留 G/C/P/R 行及状态。

数值总计必须标明“完整 / 条件 / 已知小计”及未知补充项；有未知时剩余空间仅写条件余量，不能称可用 KV。已确认的完整总计才用于容量判断。保留独立安全余量，不冒充实测占用。

## 细节与范围

详算顺序与首表一致：KVCache → 权重 → 激活/workspace → 图模式/图池 → HCCL buffer → 其他持久项 → 运行时 → 逐阶段总账。权重与KV可能在内部先算，输出顺序不代表执行依赖顺序。

沿用 KV 专项的多请求、投机预算范围及 `block_size=128` 条件回退；这些不证明部署已开启投机或采用该block。不得固定某模型 GiB、HCCL 域数、图池经验值或并发数。没有设备时交付可复算条件账，不能为补齐表格臆造实测峰值。
